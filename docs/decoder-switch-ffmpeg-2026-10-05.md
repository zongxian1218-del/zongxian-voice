# 解码器换成 libavcodec：延迟 900ms → 2.5ms（2026-10-05）

## 结果

| 指标 | 换之前（MS 解码器 MFT） | 换之后（libavcodec） | 改善 |
|---|---|---|---|
| **解码延迟（平均）** | 1041.9 ms | **2.5 ms** | **↓ 417×** |
| 解码延迟（最大） | 2259.7 ms | 19.5 ms | ↓ 116× |
| **首包→首帧** | 901.6 ms | **17.6 ms** | **↓ 51×** |
| 已重组帧 vs 已解码 | 差 27 帧（恒定积压） | **完全相等，零积压** | — |
| 解码耗时/帧 | 1.39 ms | 2.71 ms（预算 33.3 ms） | 仍只用 8% |
| 端到端丢帧 | 0 | 0 | — |

接收端每秒统计从「恒定落后 27 帧」变成**逐帧同步**：

```
换之前: [5.0秒] 已重组 24  已解码 0    延迟 903 ms
        [9.1秒] 已重组 145 已解码 118  延迟 903 ms
换之后: [5.0秒] 已重组 25  已解码 25   延迟 2 ms
        [9.1秒] 已重组 146 已解码 146  延迟 3 ms
```

## 为什么必须换（排查过程）

### 1. 确认延迟确实在解码器，不是网络

离线解码同一个码流文件（完全脱离网络），逐帧记录 `喂入数 − 已解出数`：

```
管线深度(最大): 27 帧
深度轨迹: 20→20 40→27 60→27 80→27 100→25 120→27 140→27
```

**离线批处理会把管线里的帧也排出来**，所以只统计"共解出 150 帧"完全正常 ——
必须**边喂边看**才能暴露。这是上一轮漏掉它的原因。

### 2. 排除所有可配置项

全部返回 `E_INVALIDARG`，微软这个解码器不接受任何降低管线的设置：

| 设置 | 返回 |
|---|---|
| `CODECAPI_AVDecNumWorkerThreads = 1` | `0x80070057` |
| `CODECAPI_AVLowLatencyMode = TRUE` | `0x80070057` |

编码器侧的参考帧数**确实生效了**（自写 SPS 解析确认 `max_num_ref_frames = 3`，
默认是 16），但解码器管线深度不变。

### 3. 确认没有硬件解码器可用

四种过滤条件都枚举过，只有那一个软件解码器：

```
[硬件 H264→NV12] （无）
[全部 H264→NV12] 1 个： Microsoft H264 Video Decoder MFT(异步0)
[硬件 H264→任意] （无）
[全部 H264→任意] 1 个： Microsoft H264 Video Decoder MFT(异步0)
```

### 4. 换 libavcodec

它的解码器可以显式关掉并行与前瞻：

```cpp
ctx_->thread_count = 1;                        // 不并行，避免"每线程压一帧"
ctx_->thread_type  = 0;
ctx_->flags  |= AV_CODEC_FLAG_LOW_DELAY;       // 不做前瞻
```

码流本身没有 B 帧（`has_b_frames = 0`），无需重排序，输出紧跟输入。

## 新依赖

```
D:\BuildTools\ffmpeg\ffmpeg-9.0.2-full_build-shared
```

**必须随应用一起分发 4 个 DLL**（build 脚本会自动拷到 exe 旁边）：

| DLL | 大小 | 为什么需要 |
|---|---|---|
| `avcodec-63.dll` | 98 MB | H.264 解码 |
| `avutil-61.dll` | 3.2 MB | 基础库 |
| `swscale-10.dll` | 2.4 MB | YUV420P → NV12 |
| `swresample-7.dll` | 0.5 MB | avcodec 的依赖（**漏了会 0xC0000135**） |

⚠️ **约 104 MB 的体积代价**。这是完整 GPL 构建（含所有编解码器）。
后续如果想瘦身，需要自己编译一个只含 H.264 解码的最小 FFmpeg（约 2~5 MB）。
当前优先保证功能正确。

## 踩到的坑

| 现象 | 根因 |
|---|---|
| 一堆 `LNK2019` 未解析符号，符号名是 C++ 修饰名 | **FFmpeg 公开头文件没有 `extern "C"` 保护**，C++ 里必须自己包一层 |
| `0xC0000135`（STATUS_DLL_NOT_FOUND），无其他提示 | 漏了 `swresample-7.dll`（avcodec 的间接依赖）。用 `dumpbin /dependents` 查出来 |
| 下载失败 | curl 的 schannel 走不通，且系统代理未启用；**改用 PowerShell 的 `Invoke-WebRequest`**（能走通），7z 用 Windows 自带的 `tar`（bsdtar 支持 7-Zip）解压 |
