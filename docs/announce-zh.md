## 版本 A：V2EX（发在「分享创造」节点）

**标题**：写了个和朋友互传大文件的工具，不装服务器、不要公网 IP，局域网能跑到 150MB/s

**正文**：

一直嫌微信/QQ 传大文件慢，网盘又要会员还限速，所以自己写了一个。核心就两点：**能连上、跑得满**。

**它是什么**
- 三种形态：单文件网页版（发给朋友双击就能用）、Windows 桌面版（GUI）、手机浏览器直接用
- 不经过任何服务器，文件在两台设备之间直传，端到端加密
- 不要公网 IP、不要注册、不要装服务端

**实测速度**（都是我本机跑出来的，不是宣传数字）
- 局域网 200MB：**~150 MB/s**（多路并行 TCP）
- 电脑 ↔ 手机同一 WiFi：受 WiFi 限制，一般 5~20 MB/s
- 浏览器直连（回环）：~27 MB/s
- 断点续传：4MB 分块 + SHA-256 校验，断了重来只补缺的块

**异地怎么办**（这条最重要，别抱幻想）
双方都在运营商大内网（CGNAT）时，**没有任何软件能凭空直连**，这是物理限制。我的做法是：装个免费组网工具（Tailscale / Radmin VPN），两台设备进同一个虚拟局域网，程序会**自动识别组网地址**，然后就像局域网一样多流直传。程序里也内置了 WebRTC 打洞（一边是全锥形 NAT 时能直连）。
**异地速度上限永远是"发送方上行带宽"**——家宽上行 20~30Mbps 时就是 2~4MB/s，换什么软件都一样。

**内置了个"连接诊断"面板**：显示真实 RTT、抖动、各流速度、磁盘写入占比、卡顿次数，并直接给结论（上行瓶颈 / 链路丢包 / 接收方磁盘慢），一键复制。这个是我自己被"到底慢在哪"折磨出来的。

**技术**：桌面版纯 Python 标准库（零依赖、双击即用）；网页版是单文件 HTML，无 CDN、无第三方 JS；自带一套极简 MQTT-over-WebSocket 信令 + 公共 broker 多线路。

代码 MIT 开源，欢迎提 issue / PR：https://github.com/zongxian1218-del/zongxian-transfer
下载试用（Windows 自解压版，双击即用）：https://github.com/zongxian1218-del/zongxian-transfer/releases/tag/v1.0

**已知不足**（先说清，免得被杠）：只在 Windows 打包实测过；安卓客户端已停维（手机建议用浏览器 + 组网）；macOS/Linux 没适配。

## 版本 B：小众软件（appinn，这类工具最容易被收录）

**标题**：棕仙的传输软件 —— 免安装、局域网 150MB/s、还能跨网直传大文件的传输工具

**正文**：

小众软件的朋友好，自荐一个小工具：**棕仙的传输软件**（Zongxian Transfer）。

**一句话**：朋友之间传大文件，不装服务器、不要公网 IP、不限速、无广告。

**亮点**
1. **单文件网页版**：一个 `swiftdrop.html` 发给对方，双击打开、输入 9 位取件码就能互传——对方什么都不用装。
2. **局域网极快**：多路并行 TCP（可 4~8 条流），200MB 实测 ~150MB/s，支持断点续传与 SHA-256 校验。
3. **异地可用**：配合免费的 Tailscale / Radmin VPN 组网，程序自动识别组网地址并直传（不需要中继服务器）。
4. **文件夹同步**：双向/单向、持续监控、开机自启，同步文件夹会自动换成带徽标的图标便于辨认。
5. **连接诊断面板**：把"为什么慢"说清楚（上行瓶颈 / 链路丢包 / 磁盘慢 / 中继受限）。
6. **零依赖**：桌面版只用 Python 标准库；网页版无 CDN、无第三方 JS。

**系统**：Windows 10/11（桌面版）；手机/任意系统用浏览器即可。
**授权**：MIT 开源。
**下载**：https://github.com/zongxian1218-del/zongxian-transfer/releases/tag/v1.0
**源码**：https://github.com/zongxian1218-del/zongxian-transfer

## 版本 C：少数派 / 知乎（偏"使用体验"的长文）

**标题**：受够了网盘限速，我自己写了个设备间直传工具：局域网 150MB/s、异地靠组网

（结构建议）
1. **痛点**：微信/QQ 文件过期、网盘限速、AirDrop 只有苹果、LocalSend 只能在同一 WiFi。
2. **我的选择**：直传 + 不经过服务器；异地不硬造穿透，而是借用免费组网工具（讲清物理限制，这一点最容易被读者认可）。
3. **实际体验**：贴 3 张图（网页版取件码页 / 桌面版传输中带诊断数字 / 手机扫码页）+ 一段 30 秒操作流程。
4. **实测数据表**：局域网 150MB/s、BrowserP2P 27MB/s、手机 WiFi 5~20MB/s、异地 2~4MB/s（受上行限制）。
5. **它和 LocalSend / Snapdrop / Syncthing 的区别**（见 README 的对比一节）：中文界面、单文件网页版免安装、Windows GUI、组网直传、诊断面板、断点续传。
6. **不足与计划**：macOS/Linux 未适配、安卓停维、需要组网工具才能稳定异地。
7. **结尾**：开源地址 + 求反馈（"遇到问题请附上诊断面板复制的那段文本"）。

## 短视频 / 动图脚本（抖音、B站、小红书都适用，30 秒）

1. （0-5s）左边电脑、右边手机，字幕："别再发微信传大文件了"
2. （5-12s）电脑点「打开内置网页版」→ 生成取件码 → 手机扫码 → 显示"已直连"
3. （12-20s）拖一个 2GB 文件进去，速度飙升到 100MB/s+（字幕：局域网实测 150MB/s）
4. （20-25s）再演一遍异地：两边开着组网工具，用组网地址传（字幕：异地也能直连，速度上限=你的上传带宽）
5. （25-30s）字幕 + 二维码："GitHub 开源，搜 棕仙的传输软件"

> 提示：GIF 可以用内置的「连接诊断」面板当"证据画面"——它是真实数据，比单纯的速度条更可信。

## 现实的预期（别被打击到）

- 发 3~5 个渠道 → 大概 **几百次访问、几十次下载、几个 issue**；
- 有 **1 个外部 PR** 就算成功（哪怕只是改文档/翻译）；
- "有人帮你开发"通常要 **几个月**，而且前提是：**你自己在认真回 issue、及时合并 PR、在 README 里致谢贡献者**——一个"活着的仓库"才会吸引人。
- 另一个前提：**先有用户，才有贡献者**。所以推广 > 等技术完美。
