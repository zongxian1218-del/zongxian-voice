## 为什么这个功能单独验

「共享电脑声音」是**独立功能**：不依赖屏幕共享、不依赖通话。
采的是**指定应用**（或整个系统）的声音 —— Chromium 自己做不到按应用采集，所以走的是引擎的
Windows 进程回环。这条链路今天刚打通，需要你真机确认一次"对方真的听得见"。

## 步骤（两台机器都要同一个包；包号见上注 —— v36 已作废）

1. 两台机器各自解压 → 双击 `ZongxianVoice.exe`
   （启动**直接进主界面**，不再有第一屏门槛；需要联机时点左栏「联机 / 换房间」）
2. 一边点「联机 / 换房间」→ 把「我的地址」给对方 → 对方填进去、点加入
   → 确认两边**成员列表显示 2 人**（显示真实名字，不是"对方"）
3. **先制造声音**：在那台要共享的机器上放个音乐/视频（任意播放器都行）
4. 在那台机器上：齿轮（设置）→ 找到「**共享电脑声音**」这一节
   → 点「刷新列表」→ 下拉里会出现正在发声的应用（带"正在发声"标记），第一项是"整个系统"
5. 选中 → 把开关拨到"开"
   → 界面状态文字会变成：`链路 N 条 · 推送 N 块 · 已发 N 字节 · 已收 N 字节`
   （**这些数字来自 WebRTC 的真实统计**，不是自己数的）
6. **在另一台机器上听** —— 应该能听到那台机器的声音
7. 关掉开关 → 对方应立即听不到

## 预期与判据

| 检查 | 期望 |
|---|---|
| 不需要碰屏幕共享 | 全程只用「设置 → 共享电脑声音」 |
| 列表内容 | 是你机器上**真实**在发声的应用（不写死） |
| 开关打开后 | 状态里的"**已发**"字节数持续增长；对端"**已收**"字节数也增长 |
| 关掉后 | 对方立即听不到 |
| 单应用 vs 整机 | 选具体应用 → 只传它的声音；选"整个系统" → 传全部 |

## 出问题怎么取证（不用打字描述）

设置 → **诊断与实验功能** → 「复制诊断信息到剪贴板」→ 粘回来给我。
里面包含：声音来源列表是否枚举成功、采集泵的块数/字节数/退出码、音轨挂到了几条链路、
收发字节数 —— 这几项就能定位是"没采到"还是"没传出去"。

## 已知边界（不是 bug）

- 共享"单个窗口"的**屏幕**时，系统音频不由 Chromium 提供（要声音请选"整个屏幕"）
  —— 但**电脑声音**走的是独立通道，与屏幕选什么无关
- 选择屏幕共享的窗口时，如果看不到弹窗，按 `Alt+Tab` 找「选择要共享的内容」
  （等待时间已从 20 秒放宽到 **120 秒**）
