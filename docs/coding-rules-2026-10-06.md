## 规矩一：**不许写死**

界面上的**文字 / 名字 / 数量 / 状态 / 列表行**，一律必须来自数据（事件、配置、真实对端信息），
**不许硬编码在 XAML 或 C# 里**。

### 允许写死的（白名单，仅此三类）
1. **纯静态标签**：`设置`、`关闭`、`发起通话`、`挂断` 这类按钮文字
2. **占位提示**：`PlaceholderText="输入消息…"`
3. **初始化占位**：如 `Text="启动中…"`、统计项初始 `—`
   —— 但**必须马上被真实数据覆盖**，不能长时间停在占位

### 判据（自查方法）
搜 `MainWindow.xaml` 里的 `Text="…"`，每一处都要能回答：
> **"它由哪个数据/事件决定？"**
答不上来的，就是写死 ✗。

### 本项目实际踩过的（都是用户发现的）
| 位置 | 写死的东西 | 正确来源 |
|---|---|---|
| 聊天消息名字 | `isSelf ? "我" : "对方"` | 消息的 `from` → `roster` 里的真实名字 |
| 聊天头像字 | `isSelf ? "我" : "对"` | 名字首字 |
| 成员列表 | 三行 `朋友A / 朋友B / 我` | `roster.peers` 真实成员 |
| 左栏卡片 | `和朋友的语音 / 晚上看电影 / 远程帮家人看电脑` | 真实房间列表 / 最近加入 |
| 聊天日期 | `今天` | 真实日期分组 |
| 文件消息名字 | 同聊天 ✗ | 同聊天 |

## 规矩二：**前后端分离**（UI 与功能分开）—— 为的是"一眼定位"

### 分层
| 层 | 谁 | 只做什么 | 不许做什么 |
|---|---|---|---|
| **功能层** | 页面 JS（`call.html`）+ C# 里的引擎/网络/设备代码 | 维护状态与数据，**发事件** | 不碰控件、不决定文案 |
| **UI 层** | XAML + 事件处理（`RenderXxx` / 各 `case "事件"`） | 把事件渲染成界面 | 不判断业务、不算数据 |

通信只用**事件**：
- 页面 → C#：`post({ type: '...' , ... })`（现有 48 个事件）
- C# → 页面：`zxEngine.xxx()` 调用

### 由此得到一条**定位法**（这是这条规矩最大的价值）

> **看日志里有没有对应事件。**
> - **事件对了、界面没变** → **UI 问题**（渲染/绑定/重建）
> - **事件没来、或事件本身就是错的** → **功能问题**（采集/网络/协议）
> - **事件来了但文案/数值错** → **映射问题**（UI 层把事件映射错了）

**例子（P2 那条 bug）**：
状态栏写着"建立连接"，但同一栏右侧显示 `延迟 7ms`。
→ 查 `call-link` 事件：若事件是 `connected` 而文案没跟着 → UI 问题 ✓；若事件根本没发 → 功能问题 ✓。
**先看事件，再决定改哪层** —— 不许上手就改 XAML。

### 落地要求
1. 每个界面元素都要能对应到**一个数据来源**，并登记在 `docs/ui-inventory-2026-10-05.md`
2. 新加界面元素时，同一次提交里必须写清它的事件来源
3. 修 bug 时，提交信息里注明：**这是 UI 问题还是功能问题**（按上面的定位法判定）

## 规矩四：测试必须用**模拟键鼠**（真实输入），不许"UIA Invoke + 固定 sleep"

**用户原话**："后面测试都用模拟键鼠测试，因为你测试的时间太标准了。"

### 要求
1. **操作一律走 SendInput 真鼠标/键盘**：移动 → 点击 → 输入（中文用 Unicode 注入）
   - 定位元素**可以**用 UIA（为了拿坐标/状态），但**动作不能**用 `InvokePattern.Invoke()` 代替
2. **等待一律"轮询 + 超时"**：条件满足立刻继续；**不许** `Sleep 3` 这种拍脑袋固定等待
3. 鼠标移动**插值**（像人一样滑过去），点击前先落位
4. 每个测试**必须有看门狗**：超过总时限就失败退出 —— **绝不允许挂住**（我已经因为自检挂住浪费过两轮）
5. 测试脚本失败时要能说清**卡在哪一步**（每步打时间戳与结果）

### 为什么（用户意图 + 我的教训）
- 固定 sleep + UIA Invoke **不像真人**，还会漏掉"命中/遮挡/焦点/输入法"这类真问题
- 我前两版自检都是"递归遍历/固定等待"✗ → **卡死** ✗，两次白等十分钟
- 模拟键鼠顺带能验证"**用户真的点得到这个按钮吗**"（P1/P2 那些 bug 正是这类）

### 落地
- 用 `gui-automation` skill 的 `gui.py`（ctypes 直调 Win32，不装依赖）
- 现有实现 `build\smoke-ui.ps1`（PowerShell+UIA）**作废**，改为 Python 版 `build\smoke-ui.py`
