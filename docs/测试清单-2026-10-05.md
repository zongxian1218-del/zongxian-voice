## 0. 怎么用

1. 把 `棕仙语音-测试版-v25.zip` **解压到一个空目录**（不要直接在压缩包里双击运行）。
2. 双击 `ZongxianVoice.exe`。

**两个实例在同一台电脑上跑**（测多人共享/双端）：
```
第一个（房主）：ZongxianVoice.exe --port 45891 --room test
第二个（加入）：ZongxianVoice.exe --port 45892 --signal ws://127.0.0.1:45891/signal --room test
```

## 1. 语音音质：三档降噪 A/B ★最想要的一项

**为什么**：这是唯一"必须真人说话才能判定"的遗留项。工具（客观分析）已经就绪，就差你的声音。

**怎么做**
1. 打开应用，在界面上的**降噪档位下拉**选 `关闭`（off）。
2. 点**录音自检**按钮，对着麦克风**正常说一句话**（约 3 秒，比如"今天天气不错，测试一二三四五"）。
3. 把档位切到 `正常`（normal），再录一次，**说同一句话**。
4. 再切到 `强`（strong），第三次，**还是同一句话**。
5. 三次录音会自动存到 exe 同级的 `recordings\` 里，**文件名带档位**，例如
   `mic-off-153012.wav` / `mic-normal-153045.wav` / `mic-strong-153120.wav`。

**期望看到什么**
- 三次都能录满 3 秒、文件名里档位正确、没有崩溃。
- 具体"哪档更好听"由你主观判断；**客观数字我来算**（RMS / 噪声底 / 语音带占比 / 谱质心）。

**把什么给我**：三个文件名（或把 `recordings\` 目录打包发我）。我会给出对比数字 + 一句提醒
（没有真人说话时，数字只反映底噪怎么被处理了）。

## 2. 共享时把系统声音一起带过去

**怎么做**：点共享 → 在系统弹窗里选一个**正在放音乐/视频的窗口** → 勾上"**分享系统音频**"（弹窗里的复选框）→ 开始在另一端点"观看"。

**期望**：对方能听到声音，且画面流畅。

**失败时给我**：应用日志里共享相关的行 + 对方是否报错。

## 3. 单个应用音频：它到底能不能用（这是本机的"实测空白"）

**背景（重要，先读）**：这个功能会调用 Windows 的"进程回环"接口，
**在部分机器上会让调用进程直接堆损坏崩溃**（我这边实测必崩）。
所以应用**绝不在自己进程里碰它** —— 它在 `tools\zxprobe.exe` 这个**独立子进程**里去试：
崩了就算"本机不支持"，主程序毫发无伤。

**怎么做**
1. **直接点顶栏的「音频能力」按钮**（不用命令行、也不用真的去共享）。
   —— 点共享的时候它也会在后台自己探一次，所以两种方式都行。

**看哪里**：下面日志区里会出现 `【音频能力】…` 的几行，最后一行是结论。

**期望看到什么**（两种都算正常，我要的就是这个结论）
- `[音频能力] 单个应用音频：可用` → 你的机器支持，**很好的消息**，下一步做 PCM 通路就有意义；
- `[音频能力] 单个应用音频：本机不支持…` → 机器不支持，功能会降级为"共享全部应用的声音"。

**关键**：**不管崩不崩，应用本身都不该退出、界面不该卡住。** 如果你看到应用自己没了，那是严重问题，立刻告诉我。
（`tools\zxprobe.exe` 是我**故意**打开了真实探测的版本，它崩溃是预期行为之一，不是包坏了。）

**注意**：即使探测显示"可用"，**现在也还不能真的把单个应用的声音送进通话** ——
那段 PCM 通路还没做（这是明确的遗留项，不是坏了）。

## 4. 多人共享（3 人以上同时看同一路）★现在不用敲命令了

**怎么做**（三台电脑，各自双击打开应用即可）：
1. A、B、C 都打开应用；**等 1~2 秒**，各自顶栏的"自动扫描到的房间"里应出现另外两台。
2. B 选 A → 点「加入选中」；C 也一样加入 A。
3. A 点共享（选一个窗口）。
4. B、C 点"观看"。
5. 再试一次：**C 先退出、等 A 已经开始共享之后再重新加入**（这条最容易坏，我这边已实测通过）。
6. 再试：A **停止共享**，然后再**重新开始**。

**期望**：B、C **都能**看到同一路画面，包括后加入的 C；A 停止时两端都应提示"对方停止共享屏幕"。

**如果"自动扫描到的房间"里没有对方**（先排查这三样）：
- 两台是不是真在同一个局域网/VPN（你们用 Radmin 组网的话，两边都要连着）；
- **Windows 防火墙**第一次可能会弹窗询问是否允许"棕仙语音"访问网络 → 要**允许**（专用+公用都勾）；
- 实在不行就手工：对方界面上那行"我的地址"点「复制」发你，你填进输入框点「连接」。

**失败时给我**：直接点设置图标（诊断）把内容粘给我，加上三方各自的日志区内容。

## 5. A 线安装包：快捷方式与卸载项（真机才能验的一项）

**为什么**：我这边跑自动化时，桌面/开始菜单快捷方式和"控制面板卸载项"**必然失败** ——
查清了是本开发环境**禁止写工程目录之外**（用 NSIS 的 TRACE 已证明代码确实执行到）。你自己双击安装就没有这层限制。

**怎么做**
1. 双击 `棕仙的传输软件-安装包-1.0.exe`（在 `dist\` 里，和语音包不是同一条线）。
2. 装完检查三处：**桌面**有没有图标、**开始菜单**里有没有"棕仙的传输软件"文件夹（含"卸载"/"使用说明"）、
   **控制面板 → 程序和功能**里有没有这一项。
3. 随便传个文件试试（拖进去就行）。
4. 用开始菜单里的"卸载"卸掉，确认**装的东西都清干净**。

**期望**：三处都有；卸载后干净。

**失败时给我**：哪一处没有 + 安装界面有没有报错。

## 6. 界面与稳定性（顺手看一眼就行）

- 点界面上的**"原生视频"开关**：打开后如果对端在共享，画面应显示在视频区（而不是网页里那块）。
- 拖窗口 / 最小化 / 还原：画面区域应跟着走，不该出现黑块或错位。
- 共享中切换共享的窗口：应能切过去，不该崩。
- 长时间挂机 10 分钟：日志不该刷屏、内存不该一直涨。

## 已知限制（不用报为 bug）

1. **单个应用音频的 PCM 通路没做** —— 探测能用≠功能可用。
2. 长文本/大文件聊天走 base64 DataChannel，**>64MB 没有方案**。
3. 成员列表里的名字目前是占位文字（不是真实用户名）。
4. 麦克风/耳机/设置/共享音频这 4 个按钮**还没有接事件**。
5. 覆盖窗口的 `WS_EX_TOPMOST` 在某些情况下拿不到（我们改用"锚在应用窗口正上方"绕过了，效果等价）。
