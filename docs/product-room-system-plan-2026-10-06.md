# 产品化方案：真正的房间系统 + UI 去重（待你拍板）—— 2026-10-06

> 你的要求：**"放下后面的任务，做一个真正能用的版本：有房间系统、能加多个房间、UI 功能不重复"**。
> 这属于产品形态变更，按规矩先给方案、你确认后我再动手。

## 1. 现状（UI 审计实测，不是印象）

**界面里与"联机/房间"有关的东西**：

| 位置 | 控件 | 文案 | 实际行为 |
|---|---|---|---|
| 左栏 | `SidebarRoomHint` | "还没有房间" | 只显示状态 |
| 左栏 | `SidebarConnectButton` | 「联机 / 换房间」 | 打开 `WelcomeOverlay` |
| 中栏 | `SidebarConnectButton2` | 「联机 / 换房间」 | **同一个** `WelcomeOverlay`（**重复入口**） |
| 中栏 | `RoomTitleText` | "我的房间" | 显示当前房间名 |
| 中栏 | `CopyAddressButton` | 「复制」 | 复制邀请串 `房间名@地址` |
| 浮层 | `WelcomeOverlay` | 起名字 / 局域网列表 / 填地址 | 一个浮层里塞了 4 件事 |
| 设置 | `RoomNameBox` | 房间名 | **改完要重启才生效**（代码注释自认） |

**结论**：
- **重复**：两个「联机 / 换房间」入口；`WelcomeOverlay` 一个浮层里混了"起名字 + 选房间 + 填地址 + 不联机进入"。
- **不成系统**：没有房间列表、没有切换、没有记住、不能同时保有多个房间；
  房间名散落在设置里且需重启 —— 用户原话"要连自己的房间得连自己的 IP，很别扭"。

## 2. 目标形态（我的提议）

**左栏 = 房间列表**（像聊天软件的会话列表），一屏看清所有房间与状态：

```
┌─ 房间 ────────────────┐
│ ● 周末开黑       已连接 │   ← 主机：192.168.1.5:45891
│ ○ 会议室        未连接 │
│ ○ 家里          未连接 │
│ + 新建 / 加入房间      │
└───────────────────────┘
```

- **每个房间一项**：名字 + 主机地址 + 实时状态（已连接 / 未连接 / 连接中）。
- **点一下 = 切换过去**：调已有的 `zxEngine.join({signalUrl, room})`（**这个能力已存在**，
  现在只被"填地址"那条路用到）。
- **房间持久化**：存进 `app-config.json`（已有 `AppConfig`），重启后还在。
- **唯一入口**：左栏的「+ 新建 / 加入房间」；**删掉**两个重复的「联机 / 换房间」按钮。
- **改名/删除**：每个房间项右键或用小按钮（改名、删除、复制邀请串）。
- **起名字**：挪进设置（`SelfNameBox` 已在设置里，`WelcomeNameBox` 删除）。

## 3. 取舍（要你选，因为影响"谁提供信令"）

**关键限制（现状，无法绕过）**：信令由**某一方**提供 —— 房主开 `ws://ip:端口/signal`，
加入方必须知道那个地址。所以"输入房间号就能进"必须有一个**公共信令服务**。

| 方案 | 能加多个房间 | 跨网段 | 需要什么 | 工作量 |
|---|---|---|---|---|
| **A（推荐）** 本地房间列表 | ✅ | ❌（仍靠房主地址可达 / 组网工具 / TURN） | 无 | 小（1 个工作单元） |
| **B** A + **自建公网信令**（6 位房间号） | ✅ | ✅ | **一台常驻服务器 + 域名** | 中（含部署与安全） |
| **C** A + 局域网自动发现改进（同名房间合并、一键加入） | ✅ | ❌ | 无 | 小 |

**我建议先做 A（含 C 的局域网改进）**：它立刻把"多房间 + 切换 + 记住"做出来，
且**不挡 B** —— 将来有服务器时，房间项里的地址换成服务器地址即可。

## 4. 完成后你会得到什么（可验收）

1. 左栏能**同时看到多个房间**，点一下切换，状态实时；
2. 房间**重启后还在**（不用每次重新填地址）；
3. 界面上**只有一个**"新建/加入房间"入口，`WelcomeOverlay` 与重复按钮删除；
4. 起名字、房间名都在设置里，改完**不需要重启**（房间名即时生效）；
5. 判据（自动）：`check_room_store`（房间增删改查持久化）、
   `check_ui_no_duplicate_entry`（同一功能只有一个入口）、
   三实例实测（三个房间/三个实例互不串台）。
