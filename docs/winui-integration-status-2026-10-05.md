# WinUI 集成：进展与未解问题（2026-10-05）

## 已确认的结论

### 1. WinUI 3 里不能用子窗口嵌入 —— 这条走不通

用 `--parent-hwnd <HWND>` 把助手的窗口建成 WinUI 窗口的 `WS_CHILD` 子窗口，
**助手侧一切正常**（日志：收包 4243 / 解码 300 帧），但界面上**一片黑**。

根因：WinUI 3 把 XAML 内容渲染在一个 `DesktopChildSiteBridge` 子窗口里，
我们的窗口是它的**兄弟窗口**，而 WinUI 会持续把内容岛提到 z 序最前，把它盖住。
`SetWindowPos(HWND_TOP)` 抢不过它。

**这个结论很重要**：以后不要再尝试"往 WinUI 里塞原生子窗口"这条路。

### 2. 无边框顶层覆盖窗口可行 —— 已独立验证

`--frameless --topmost --pos x y` 创建 `WS_POPUP` + `WS_EX_TOOLWINDOW` +
`WS_EX_NOACTIVATE` 的顶层窗口，**脱离 WinUI 单独测通过**：
在 (200,150) 处显示出了推流过来的桌面内容（豆包面板、信号模式面板都清晰可见）。

### 3. WinUI 应用 + 覆盖窗口的集成 —— 未验证通过

最后一次尝试里：
- 助手侧日志显示窗口创建成功（无边框覆盖窗口），并收到了数据
- 但截图里应用视频区仍然是黑的
- 加了位置诊断后，C# 侧的位置文件**没有生成**，说明 `RootGrid.Loaded` 里的
  自动启动**没有执行**

**当前状态：不确认覆盖窗口在 WinUI 场景下是否可见、位置是否正确。**
需要下一轮继续排查（见下）。

## 下一轮要做的

1. **先查清 C# 侧为什么没自动启动**。
   `RootGrid.Loaded` 在 `VideoProbe` 里没触发（位置文件没生成）。
   换成在 `App.OnLaunched` 里启动，或直接用按钮点击 —— 先不要依赖 `Loaded`。
2. **把助手的窗口矩形日志和 C# 算出的坐标对齐**（两边都加好了日志，只差一次能跑起来的运行）。
3. 确认覆盖窗口在 WinUI 窗口上方可见后，再处理这些已知缺陷：
   - **缩放**：目前 `CopyResource` 要求覆盖窗口尺寸 == 视频尺寸，
     所以视频区必须正好 1280x720。要支持任意尺寸得改用 VideoProcessor 做 BGRA→BGRA 缩放。
   - **跟随窗口**：应用窗口移动/最小化时覆盖窗口要同步移动/隐藏。
     已在 `AppWindow.Changed` 里挂了对 `rect` 的同步，但最小化还没处理。
   - **点击穿透**：覆盖窗口会吃掉鼠标事件。做远程控制时这是需要的，
     但届时要区分"本地操作"和"远程注入"。
4. 之后再把这套搬进主应用 `src/winui-cs/`。
