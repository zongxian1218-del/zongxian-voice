## 2. 功能类（用户实测"问题很多"的部分）

### P4 · 共享音频完全失效 ⚠️
- **现状**：共享走 `getDisplayMedia({ video, audio })`，`audio` 由设置里的开关决定。
- **要查三件事**（按顺序）：
  1. 系统弹窗里**有没有**"共享系统音频"复选框（没有 → 约束写法不对）
  2. 勾了之后页面有没有拿到音频轨（日志 `remote-track kind=audio`）
  3. 音频轨有没有被 `addTrack` 进链路（对端有没有收到）
- **改哪里**：待查清后定 —— 可能在 `call.html` 的 `startScreenShare` 约束、或加轨逻辑。
- **怎么验证**：双实例共享 → 对端日志应出现 `remote-track kind=audio` + 截图音频电平/统计的码率上升。
- **风险**：Chromium 在 Windows 上共享系统音频有已知限制，可能只能"整机声音"而不能"单个应用"。

### P3 · 屏幕共享时好时坏 ⚠️【最难】
- **现象**：有时能显示、有时不能。
- **要做的第一步不是改代码，而是"让它说清楚失败原因"**：
  - 采集失败（弹窗没选/超时/被占用）与"采集成功但没上屏"是两条完全不同的路，日志里 `screen-*` 事件能区分。
  - 现有 `--screen-cycle` / `screen-probe` 能脚本化验证"合成源"路径；真实窗口采集必须人工。
- **改哪里**（待复现后定，候选）：
  - 采集失败 → 给出可读原因 + 允许一键重试 ✅
  - 资源被占用（房间里有别人在共享）→ 明确提示"等对方停止后再试" ✅
- **怎么验证**：复现 3 次以上、每次带诊断信息（设置 → 诊断 → 复制）；我截屏复核。
