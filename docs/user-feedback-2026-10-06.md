## P1 · 成员列表只显示两个人（用户："这个界面它只能看到你我…就两个"）

**待澄清**：是"三个人在房间里也只显示两行"，还是"只能看到自己和对方"？
**我的初步判断**：`roster`/`peer-joined` 是逐个维护的，多人应该都能进列表 —— 需要一次三实例实测来确认到底是数据没来、还是布局/重建把它盖掉了。

## P2 · 通话状态显示不对：明明已经通话，界面还写"正在建立"【已用截屏确认】

- 截屏帧 f055：底部状态文字是 **"建立连接"**，而同一条状态栏右侧同时显示 `延迟 7 ms 丢包 0.0%` ✗ → **状态文案与实际不符**。
- 用户另提到还有一处显示类似"正在建立/紧急收…"（口述转写不清，**待确认原文**）。
- 判断：`call-state` / `call-link` / `connection-state` 三个事件分别改文案，存在互相覆盖或漏更新（代码里就有一段注释说"状态位只能由 call-link 独占决定，否则会漏出假状态"）。**这是纯界面状态 bug，最容易修也最影响信任**。

## P3 · 屏幕共享"有时能显示、有时显示不出来"

- 用户："它经常是显示不出来，有时候能显示出来，有时候不能显示。"
- 线索：应用走 WebView2 的 `getDisplayMedia`（系统弹窗选窗口）；另有原生视频通道（覆盖窗口）开关在"设置 → 诊断"里。
- 需要定位：是**采集成功但画面没上屏**，还是**采集本身失败**（弹窗被挡/超时/被占用）。应用日志里 `screen-*` 事件能区分。
- 注意：这是"时好时坏"，属于最难查的一类 —— 必须**带上日志复现**，不能凭猜。

## P4 · "共享音频"完全失效

- 用户："这个音频共享功能是完全失效的。"
- 代码现状：共享时 `audio = ShareAudioSwitch.IsOn`（设置里的开关），走 `getDisplayMedia({ video, audio })`。
- 需要确认：系统弹窗里**有没有**"共享系统音频"复选框；勾了以后对端有没有收到音频轨（日志 `remote-track kind=audio`）。
- 可能原因（待验）：Chromium 在 Windows 上共享系统音频需要特定约束/用户勾选；或音频轨没被 `addTrack` 到链路。

## P5 · 没有"房间"概念：要连自己的房间得填自己的 IP，很别扭

- 用户原话："没有建立房间功能，就是你要连自己的房间，得连自己的 IP，很别扭。"
- 现状：每台机器自己起信令服务，加入方必须知道**房主的 IP:端口**（或靠 UDP 45880 局域网广播发现）。
- 用户期望：**建房间 / 用房间号加入**，而不是填 IP。
- 这是**产品形态**问题，涉及取舍：局域网广播（现成，仅同网段）／自建信令服务器（要部署）／第三方信令（要账号）／房主开洞（要打洞成功）。→ **留给"重定目标"讨论**。
