# 棕仙语音 · UI 设计规范（参考 Oopz / Discord）

日期：2026-10-04
定位：Windows 桌面端（WinUI 3 / C++）
参考：Oopz（中文语音社区，布局与配色取向）、Discord（信息架构与交互惯例）

---

## 1. 为什么参考这两个

| 参考对象 | 学它什么 | 不学什么 |
|---|---|---|
| **Discord** | 信息架构：服务器 → 频道 → 会话三级；成员列表常驻右侧；语音控件固定在左下角；说话时头像描边发光的反馈方式 | 它偏重的社区/机器人体系，我们是朋友间小规模（2~4 人） |
| **Oopz** | 中文语境下的命名与文案；更紧凑的间距；国内用户对"开黑/房间"的直觉 | 它的游戏侧功能 |

**我们的差异化**（不要把 Discord 整套搬过来）：

1. **规模是 2~4 人**，不是几百人服务器 → 不需要"服务器列表"这一层，
   左侧直接是"会话/房间列表"。
2. **核心是临时通话**，不是长期社区 → 首页应该让"发起通话"最显眼。
3. **有屏幕共享 + 远端控制**这两个 Discord 免费版没有的能力 → 要有专门的位置。

## 2. 三栏布局

```
┌──────┬──────────────────────────────────┬──────────────┐
│      │  顶栏：房间名 · 连接质量 · 共享按钮  │              │
│ 左栏 ├──────────────────────────────────┤   成员列表   │
│      │                                  │              │
│ 会话 │        主区域                    │  👤 我        │
│ 列表 │   （三选一，见下）                │  👤 朋友A  🔊 │
│      │                                  │  👤 朋友B  🔇 │
│ 56px │                                  │              │
│ 宽   │                                  │  224px 宽    │
├──────┴──────────────────────────────────┤              │
│  左下：我自己（麦克风/耳机/设置）          │              │
└─────────────────────────────────────────┴──────────────┘
```

尺寸（对齐 Windows 11 的习惯，不照抄 Discord 的 72px 服务器栏）：

| 区域 | 宽度 | 说明 |
|---|---|---|
| 左栏（会话列表） | **240px**（可折叠到 56px） | Discord 是 72+240 两级；我们只要一级 |
| 中间主区域 | 自适应，最小 480px | |
| 右栏（成员列表） | **224px**（可关闭） | 2~4 人时其实可以更窄，但留出共享预览的位置 |
| 顶栏 | 48px | |
| 左下自我区 | 56px | Discord 的语音控件位置惯例 |

## 3. 主区域的三种形态

中间主区域按当前状态切换，**不要做成标签页**（标签页会让人以为是并行功能，
而这三者是同一个房间的不同阶段）：

### 3.1 文字形态（默认）

```
┌────────────────────────────────────────┐
│  今天                                    │
│  ┌──┐ 朋友A            14:02            │
│  │头│ 晚上一起看个片子？                 │
│  └──┘                                   │
│  ┌──┐ 我               14:03            │
│  │头│ 行，我把屏幕共享一下                │
│  └──┘  ┌──────────────────────┐         │
│        │ 📄 设计稿.pdf  2.4 MB │  ← 文件卡片
│        │ 已发送               │         │
│        └──────────────────────┘         │
├────────────────────────────────────────┤
│  [+] 输入消息…                  [发送]  │  ← 支持拖拽文件到这里
└────────────────────────────────────────┘
```

### 3.2 通话形态

```
┌────────────────────────────────────────┐
│  ┌────────────┐  ┌────────────┐        │
│  │  朋友A      │  │  朋友B      │        │
│  │  [视频/头像] │  │  [视频/头像] │        │
│  │  🔊 说话中   │  │            │        │
│  └────────────┘  └────────────┘        │
│                                        │
│  我自己（小窗，可拖动）                   │
└────────────────────────────────────────┘
```

说话中的反馈（Discord 的做法）：**头像外圈描边发光 + 名字前小图标**，
不要用频谱条（太吵）。描边颜色用主题绿，粗细随音量变化。

### 3.3 共享形态

```
┌────────────────────────────────────────┐
│  ┌──────────────────────────────────┐  │
│  │                                  │  │
│  │        屏幕内容（主画面）          │  │
│  │                                  │  │
│  └──────────────────────────────────┘  │
│  [窗口▾] 1080p30 · 3.2 Mbps · 延迟 42ms │
└────────────────────────────────────────┘
```

**共享者自己的界面**：主区域显示"正在共享"的预览 + 显眼的红色停止按钮，
并且**始终显示共享边框提示**（系统那个黄框之外，我们自己也提示一次）。

## 4. 远端的控制权 UI（这一块要特别设计）

这是全应用里**信任等级最高**的交互，视觉上必须和普通操作明显区分。

### 4.1 被控方（交出控制权的人）

```
┌──────────────────────────────────────────────────────┐
│ 🔴 朋友A 正在控制你的电脑          [停止控制] [收回]    │  ← 常驻红色横幅
└──────────────────────────────────────────────────────┘
```

要求：
- **位置固定在顶部**，不随滚动消失；任何页面状态下都可见
- 用**唯一的红色**（整个应用只有这一处用纯红），确保一眼能认出
- 「停止控制」按钮最大、最显眼，**一次点击立即生效**，不弹二次确认
  （紧急情况下多一次确认就是错的设计）
- 控制期间窗口关闭按钮要拦截：提示"对方正在控制你的电脑，确定退出？"

### 4.2 控制方（拿到控制权的人）

```
┌──────────────────────────────────────────────────────┐
│ 🟢 你正在控制 朋友A 的电脑       [释放控制] [键盘 ⌨]  │
└──────────────────────────────────────────────────────┘
```

- 用绿色区分"我拿到了控制权"与"我被控制"
- 「键盘」开关：默认**关闭**，打开后才把键盘输入发过去
  （避免用户只是移动鼠标却意外敲进去东西）
- 鼠标指针状态要能看出来（远端的指针位置有独立标记）

### 4.3 请求授权时的弹窗（被控方收到）

```
┌────────────────────────────────────┐
│  朋友A 请求控制你的电脑              │
│                                    │
│  允许后，对方可以操作你的鼠标和键盘。 │
│  你可以随时点顶部红色横幅收回控制权。 │
│                                    │
│  ☐ 记住这个选择（本会话内）          │
│                                    │
│      [拒绝]        [允许控制]        │  ← 默认焦点在「拒绝」
└────────────────────────────────────┘
```

**默认焦点必须在「拒绝」**，而且**默认 30 秒无响应视为拒绝**（不给"不回答就自动同意"）。

## 5. 配色：用 WinUI 的主题系统，不自造品牌色

**原则：排版参考 Oopz / Discord，配色不参考它们。**

早先版本照抄了 Discord 的 `#1E1F22` / `#2B2D31` / `#5865F2` 那套固定色值。
这是错的——那两个是**深色为主**的网页产品，而我们要做的是**符合 WinUI 的
原生应用**。自造固定色会带来三个问题：

1. 系统切换明暗主题时界面不变，与其它 Windows 应用格格不入；
2. 丢失 WinUI 的层次体系（Fluent 的填充层级是有语义的，不是随便选深浅）；
3. 无障碍/高对比度模式下文字对比度可能不达标。

**正确做法：全部用 WinUI 的语义画刷（`ThemeResource`），系统自动跟随明暗。**

### 5.1 用哪些（按用途，不按颜色）

| 用途 | WinUI 资源 | 说明 |
|---|---|---|
| 窗口背景 | **Mica**（`SystemBackdrop`） | WinUI 3 原生材质，桌面壁纸透色 |
| 内容区卡片 | `CardBackgroundFillColorDefaultBrush` | 卡片标准填充 |
| 输入框 | `ControlFillColorDefaultBrush` | 控件标准填充 |
| 侧栏（比内容区略深/略浅一层） | `LayerFillColorDefaultBrush` 或 `SolidBackgroundFillColorSecondaryBrush` | "层"语义，不是固定灰 |
| 主文字 | `TextFillColorPrimaryBrush` | |
| 次要文字 | `TextFillColorSecondaryBrush` | 时间戳、说明 |
| 更弱的文字 | `TextFillColorTertiaryBrush` | 占位符 |
| 分隔线 | `DividerStrokeColorDefaultBrush` | |
| 强调色（按钮/选中） | `AccentFillColorDefaultBrush` | **跟随系统强调色**（用户可在设置里改），比写死 `#5865F2` 更"正式" |
| 悬停 | `SubtleFillColorSecondaryBrush` | WinUI 标准的微妙填充 |
| 选中 | `SubtleFillColorTertiaryBrush` | |
| 危险/停止 | `SystemFillColorCriticalBrush` | 系统级"严重"色 |

### 5.2 唯一需要自定义的语义色

只有两个状态色 WinUI 没有现成的对应项，需要自己定义**语义键**
（而不是把色值散落在 XAML 里），并且仍然放进 `ThemeDictionaries` 两套：

| 语义键 | 含义 | 建议取值 |
|---|---|---|
| `ZxSpeakingBrush` | 说话中（头像描边、名字前图标） | 暗色 `#6CCB5F` / 亮色 `#0F7B0F`（绿色系，与系统强调色区分） |
| `ZxControlGrantedBrush` | 我拿到控制权 | `#23A55A` / `#1A8C4A` |

「我正在被远端控制」用 `SystemFillColorCriticalBrush`，**不再自造 `#DA373C`**。
它仍是全应用唯一使用"严重红"的地方，这个约束保留（见 §4.1）。

### 5.3 主题切换

- 默认**跟随系统**（`ElementTheme::Default`），不强制暗色；
- 设置里提供「跟随系统 / 浅色 / 深色」三选，用 `RequestedTheme` 覆盖；
- 标题栏用 `TitleBar.PreferredTheme` 同步，避免标题栏与内容区割裂。

> 早先版本 `ApplyTheme()` 里写死了 `ElementTheme::Dark`，需要改掉（见 §7 待办）。

### 5.4 字号与字体（这部分保持）

字体：`Microsoft YaHei UI` 为主，等宽场景用 `Cascadia Mono`。
字号沿用 WinUI 的 `TextBlock` 预设而不是硬编码 px：正文用
`Body`（14px）、次要 `Caption`（12px）、标题 `Subtitle`（20px）。
颜色和字号都用语义资源，界面才能算"符合 WinUI"。

## 6. 不要做的事（避免做成"Web 味"的界面）

既然要 WinUI，就要用它的原生控件与交互习惯，别把网页那套搬过来：

| ❌ 不要 | ✅ 要 |
|---|---|
| 自绘按钮和滚动条 | 用 `Button` / `ScrollViewer` 原生样式 |
| 网页式 hover 阴影 | 用 WinUI 的 `SubtleFillColorSecondaryBrush` |
| 自定义窗口标题栏（除非必要） | 用 `ExtendsContentIntoTitleBar` + 系统标题栏按钮 |
| 圆角随意定 | 统一用 4px（控件）/ 8px（卡片），与 WinUI 一致 |
| 自己做右键菜单 | 用 `MenuFlyout` |
| 自己做通知 | 用 `AppNotification`（Windows 通知中心） |
| 无键盘导航 | 全部控件可用 Tab 遍历，Enter/Space 可激活 |

**特别注意**：远端控制的"停止控制"必须能用**键盘**触发并撤销
（例如 `Ctrl+Alt+Shift+Esc` 全局快捷键），因为在被控状态下鼠标可能被对方占用。

## 7. 与当前 W0 的关系

本文档是 **W1 之后**的界面规范。W0 阶段只做两件事：

1. 验证 C++/WinUI 3 能编译运行（空窗口即可）
2. 空窗口上先把**三栏骨架**搭出来，不接任何功能

### 7.1 W0 已写代码中需要修正的地方

`src/winui/` 下的首版骨架是按"照抄 Discord 配色"写的，需要改成 §5 的语义画刷：

| 文件 | 现状 | 要改成 |
|---|---|---|
| `src/App.xaml` | 定义了 `ZxSidebarBrush` / `ZxTextPrimary` / `ZxAccentBrush` 等 12 个固定色值 | 只保留 §5.2 的两个语义色；其余全部改用 WinUI 内建资源，删掉 `ThemeDictionaries` 里的大段色值 |
| `src/MainWindow.xaml` | 用 `{ThemeResource ZxSidebarBrush}` 等自定义键、散落的 `#232428` / `#4E5058` 硬编码 | 换成 `CardBackgroundFillColorDefaultBrush` / `LayerFillColorDefaultBrush` / `TextFillColorPrimaryBrush` 等；硬编码色值清零 |
| `src/MainWindow.cpp` | `ApplyTheme()` 里写死 `ElementTheme::Dark` | 改为 `ElementTheme::Default`（跟随系统），并保留设置项覆盖的能力 |

> 这件事值得单独记一笔：**"参考某个产品的 UI"要分清是参考排版还是参考配色。**
> 排版（信息架构、栏宽、控件位置）跨平台通用，值得借鉴；
> 配色应该交给宿主平台的主题系统，否则做出来的东西"像网页"而不是"像 Windows 应用"——
> 而这恰好与选用 WinUI 的初衷相反。
